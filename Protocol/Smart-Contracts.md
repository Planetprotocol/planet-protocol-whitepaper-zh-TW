# 智慧合約

Planet Protocol 的鏈上基礎設施由**五個核心智慧合約**構成,共同治理一次批次融資操作的完整生命週期。所有合約部署於**以太坊主網**,以 **Solidity ^0.8.20** 撰寫,並建構於 **OpenZeppelin v4** 標準函式庫之上。

---

## 架構總覽

```
                    ┌──────────────┐
                    │ BatchFactory │
                    └──────┬───────┘
                           │ 部署(最小代理複製)
              ┌────────────┼────────────┐
              ▼            ▼            ▼
      ┌──────────────┐ ┌───────────┐ ┌────────────┐
      │ PlanetRWA1155│ │PrimarySale│ │ EscrowVault│
      └──────────────┘ └───────────┘ └─────┬──────┘
                                           │
                                    ┌──────▼──────┐
                                    │  ClaimVault  │
                                    └─────────────┘
```

每次批次部署都會建立一組相互連結的合約實例。系統採用**最小代理複製模式**(EIP-1167)以降低 gas 成本——每個新實例委派呼叫至預先部署的實作合約,而非重複部署完整位元組碼。

---

## 合約規格

### 1. BatchFactory

工廠合約是批次建立的唯一入口。它負責為每個新批次原子性地部署全部四個子合約。

**職責:**
- 部署 PlanetRWA1155、PrimarySale、EscrowVault 與 ClaimVault 的最小代理複製實例
- 在初始化過程中將四個合約彼此連結
- 儲存所有已部署批次的登錄資料
- 強制執行部署時的參數設定(募資目標、代幣供應量、里程碑排程、費率)

**存取權限:** 僅限經授權的部署者(Planet Labs 管理員角色)。

### 2. PlanetRWA1155

代幣合約採用 **ERC-1155** 多代幣標準,用以表示批次中的碎片化持份。

**職責:**
- 於初級銷售期間鑄造 RWA 代幣
- 追蹤碎片化批次持份的所有權與餘額
- 支援領取流程所需的銷毀操作
- 儲存批次層級的中繼資料(URI、批次參數)

**設計考量:** 選用 ERC-1155 而非 ERC-20 或 ERC-721,理由如下:
- 單一合約即可表示多種代幣類型(為未來的多層級批次預留空間)
- 原生的批次轉移支援可降低投資組合操作的 gas 成本
- 透過代幣 URI 標準提供中繼資料擴充性

**可轉讓性:** 代幣合約並未限制轉讓。持有人可隨時將 RWA 代幣轉給任何地址,僅受全域暫停機制約束。Planet Protocol 並未營運任何次級市場場所,亦不保證任何批次會存在交易場所,但轉讓本身不受合約阻擋。

**單一代幣 ID:** 每個批次部署各自的代幣合約,僅使用單一 ID。多層級批次尚未實作。

### 3. PrimarySale

銷售合約負責 RWA 代幣對參與者的初次發行。

**職責:**
- 接收參與者的 USDC,並以原子方式處理每一筆購買
- 每筆購買時:扣除鑄造費並轉入 Planet Labs 國庫、將淨額轉入 EscrowVault、透過 PlanetRWA1155 鑄造對應代幣——全部在同一筆交易中完成
- 強制執行銷售截止時間與份額上限
- 提供 `getQuote()`,參與者可於購買前查詢確切的總額、費用與淨額

**不設最低募集額:** 本合約設有上限(`capShares`)但不設下限。低於目標即結束的銷售不會自動失敗或退款。解除認購不足的批次,需由營運方將託管標記為失敗。

**管理函式:** `withdrawFunds()` 允許管理角色移轉本合約持有的任何 USDC。正常運作下餘額為零,因為每筆購買都會立即將淨額轉入託管。

**計價幣別:** 所有初級銷售均以 USDC(ERC-20 穩定幣)計價。

### 4. EscrowVault

託管合約是核心的資金管理機制。它持有全部批次資金,並依預先定義的里程碑排程撥付予融資方。

**職責:**
- 隨著銷售進行,逐筆接收來自 PrimarySale 合約的淨額(已扣費)
- 管理治理批次生命週期的**七狀態有限狀態機**
- 於獲授權確認後,足額撥付各里程碑款項予融資方——此階段不再扣除任何費用
- 處理失敗狀態轉換與參與者退款,退款窗口為 180 天
- 窗口關閉後,將未退還的殘餘金額掃入設定的接收地址

**部署後仍可設定的項目:** 里程碑比例於批次 finalize 時設定,而非部署時。融資方的收款地址可由託管管理角色透過 `setFarmer()` 變更。

完整狀態機規格請參閱 [EscrowVault](EscrowVault.md)。

### 5. ClaimVault

領取合約負責在批次完成後,將回款分配予代幣持有人。

**職責:**
- 接收來自融資方或 EscrowVault 的回款存入(本金加收益)
- 接收由持有 `DEPOSITOR_ROLE` 的地址存入的回款,該角色由工廠授予該批次的 SPV
- 於營運方呼叫 `openClaim()` 時開啟領取窗口,同時對代幣供應量進行快照並固定每股給付額。合約要求存入金額非零且代幣鑄造已鎖定,但本身並不驗證存入金額是否等於約定回款——該判斷屬於營運層面
- 窗口一經開啟即不再接受存入,因此每股比率無法變動
- 自 `openClaim()` 呼叫時起,執行為期 **180 天**的領取窗口
- 窗口關閉後,將未領取的殘餘金額掃入設定的接收地址
- 處理銷毀領取贖回作業:代幣持有人銷毀其 RWA 代幣並取得相應比例的 USDC
- 確保存入總額與領取總額之間帳目精確相符
- 透過銷毀機制防止重複領取(已銷毀的代幣無法再次使用)

完整贖回機制請參閱[銷毀領取機制](Burn-to-Claim.md)。

## 安全模型

### 角色權限控管

所有合約皆採用 OpenZeppelin 的 **AccessControl** 模組,設定下列角色:

| 角色 | 範圍 | 指派對象 |
|---|---|---|
| `DEFAULT_ADMIN_ROLE` | 完整管理控制權 | Planet Labs 多重簽名錢包(移交後) |
| `DEPLOYER_ROLE` | 透過 BatchFactory 建立批次 | Planet Labs 部署者 |
| `OPERATOR_ROLE` | 里程碑確認、狀態轉換 | Planet Labs 營運者 |
| `PAUSER_ROLE` | 緊急暫停功能 | Planet Labs 管理員 |

### 部署後的管理權移交

完成初始部署與設定後,部署帳戶將放棄其高階權限,並將管理控制權移交至指定的多重簽名錢包。此舉確保系統上線後,不存在任何單一金鑰可片面修改合約狀態或存取權限。

### 升級路徑

現行合約**不可升級**。批次已部署的邏輯無法變更。協議層級的變更透過新的實作合約導入,供未來批次複製使用,既有批次則持續依其原始邏輯運作。

此點與「設定」有別:部署後仍有數項參數可由角色持有者調整,包括里程碑比例(於 finalize 時設定)、融資方收款地址、殘餘接收地址,以及國庫地址。

## 稽核狀態

智慧合約**尚未**經由第三方資安機構稽核。完整稽核預計於正式批次上線主網前完成。關於未稽核合約的風險說明,請參閱[風險揭露](../Risks.md)。
