# 銷毀領取機制

**銷毀領取**(Burn-to-Claim)是 Planet Protocol 的收益分配系統,透過 **ClaimVault** 合約實作,為代幣持有人提供一套具確定性且不可竄改的批次回款贖回方式。

---

## 機制概述

批次完成全部三個里程碑後,回款(本金加收益)由持有存入角色的該批次 SPV 存入 ClaimVault。營運方隨後開啟領取窗口,此時對代幣供應量進行快照並固定每股給付額。代幣持有人**銷毀**其 ERC-1155 RWA 代幣以領取相應比例的資金。窗口開啟後為期 **180 天**。

核心原則相當單純:**銷毀一枚代幣,即結清一筆按比例計算的請求權**。銷毀會永久消滅該代幣,確保每筆請求權僅能行使一次。

---

## 領取流程

```
   融資方                   ClaimVault                代幣持有人
       │                          │                          │
       │    存入回款(USDC)      │                          │
       │─────────────────────────►│                          │
       │                          │                          │
       │                          │      銷毀 RWA 代幣       │
       │                          │◄─────────────────────────│
       │                          │                          │
       │                          │      轉出 USDC           │
       │                          │─────────────────────────►│
       │                          │                          │
```

### 逐步說明

1. **回款存入** — 融資方將全額回款(本金加收益)以 USDC 轉入 ClaimVault 合約。

2. **發起領取** — 代幣持有人呼叫 ClaimVault 的 `claim()` 函式,指定欲銷毀的代幣數量。

3. **代幣銷毀** — ClaimVault 呼叫 PlanetRWA1155 合約的 `burn()`,自持有人餘額中永久銷毀指定數量的代幣。

4. **USDC 轉出** — ClaimVault 計算並將對應比例的 USDC 轉入持有人錢包。

---

## 領取計算

每位持有人可領取的金額計算方式為:

```
領取金額 = (銷毀代幣數 / 快照供應量) × 已存入總額
```

其中:
- `銷毀代幣數` = 持有人在本次交易中銷毀的 RWA 代幣數量
- `快照供應量` = 領取窗口開啟當下所記錄的代幣供應量
- `已存入總額` = 窗口開啟前存入 ClaimVault 的 USDC 總額

**範例(僅供說明用途——以下數字為假設值,僅用於示範計算方式,不代表任何收益預測):**
- 代幣總供應量:10,000
- 金庫總餘額:102,000 USDC——此為假設的回款數字。實際回款條件依各批次設定,並於批次建立時揭露,詳見[單位經濟](../Economics/Unit-Economics.md)
- 持有人銷毀 500 枚代幣
- 領取金額:(500 / 10,000) × 102,000 = **5,100 USDC**

## 設計特性

### 無法重複領取

銷毀機制本質上即可防止重複領取。代幣一經銷毀,即自持有人餘額與總供應量中永久移除,無法重新鑄造或回復。

### 部分領取

持有人不必一次銷毀全部代幣,可於窗口期內分多次執行部分領取。每次給付均依窗口開啟時所取得的快照計算,因此每次領取的比率完全相同。

### 原子性執行

每筆領取交易均具原子性——銷毀與 USDC 轉出在同一筆交易中完成。若任一操作失敗,整筆交易將回滾。不存在代幣已銷毀但資金未轉出的中間狀態。

### 比率在任何人領取之前即已固定

開啟領取窗口會對代幣供應量進行快照,並固定每股給付額。自該時點起,合約拒絕任何後續存入,因此每股比率無法變動。所有持有人無論在窗口期內何時領取,皆以相同比率贖回,提早或延後領取都不具優勢。

關於窗口如何開啟,有一點需要理解:合約僅要求存入金額非零且代幣鑄造已鎖定,本身並不檢查存入金額是否等於約定回款。確保全額到位後才開啟窗口,是 Planet Labs 的營運承諾,而非智慧合約強制的保證。持有人可於領取前在鏈上查驗已存入的總額。

### 180 天領取期限

自窗口開啟時刻起,領取開放 **180 天**。暫停代幣並不會延長此期限——截止時間固定為開啟時間戳加 180 天。

### 窗口結束後的未領取資金

窗口關閉後,營運方可將任何未領取的餘額掃入由工廠設定的接收地址。**未在 180 天內完成領取的持有人,其份額將歸入該地址。**參見[領取與退款期限風險](../Risks.md#領取與退款期限風險)。

## 邊界情況

| 情境 | 處理方式 |
|---|---|
| 持有人以零代幣發起領取 | 交易回滾 |
| 持有人銷毀數量超過其餘額 | 交易回滾 |
| ClaimVault 餘額為零 | 交易回滾(無資金可分配) |
| 回款分批存入 | 窗口關閉期間允許,存入金額持續累積。窗口一經開啟即拒絕後續存入 |
| 代幣全數銷毀後金庫殘留零頭 | 由整數捨去處理,可能殘留極微量金額 |

---

## 為什麼採用銷毀領取?

其他分配機制曾被評估並排除:

| 方案 | 問題 |
|---|---|
| 空投(推送式) | gas 成本隨持有人數量線性成長,且由發送方全額承擔 |
| Merkle 領取(快照式) | 需鏈下產生快照,增加信任假設 |
| 比例串流 | 對離散的批次結算而言過度設計 |
| **銷毀領取(拉取式)** | **各持有人自付 gas;無需快照;透過代幣銷毀自我強制執行** |

就 Planet 的批次結算模型而言,銷毀領取是資金效率最高、信任假設最少、gas 負擔最公平的分配方式。
