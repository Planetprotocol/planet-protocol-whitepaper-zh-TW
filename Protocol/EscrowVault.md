# EscrowVault 託管金庫

EscrowVault 是 Planet Protocol 的核心資金管理合約。它實作了一套**七狀態有限狀態機**,治理批次資金的完整生命週期——從初始存入、依里程碑分階段撥款,到最終結算或失敗後的資金回收。

---

## 狀態定義

| 狀態 | 說明 |
|---|---|
| **Empty** | 初始狀態。金庫已部署,但尚未發生任何一筆購買。 |
| **Funding** | PrimarySale 進行中。每筆購買都會立即將其淨額(購買金額扣除鑄造費)轉入本金庫,餘額隨銷售進行而累積。 |
| **Funded** | 銷售已結束,且營運方已呼叫 `finalize()`,設定融資方地址與里程碑比例。資金鎖定,等待首個里程碑確認。 |
| **Milestone 1** | 第一期款項已撥付予融資方(例如種植階段資金)。 |
| **Milestone 2** | 第二期款項已撥付(例如生長與維護階段資金)。 |
| **Milestone 3** | 最後一期款項已撥付,批次生命週期完成,等待融資方回款。 |
| **Failed** | 終端失敗狀態。由募資不足、融資方違約或營運失誤觸發。 |

## 狀態轉換

### 有效轉換

| 由 | 至 | 觸發條件 |
|---|---|---|
| Empty | Funding | 首筆購買將淨額存入本金庫 |
| Funding | Funded | 銷售已結束且營運方呼叫 `finalize()`。不設最低募集額:無論實際售出多少皆可完成 finalize |
| Funding | Failed | 營運方呼叫 `markFailed()`。這是裁量行為,並非未達目標時的自動反應 |
| Funded | Milestone 1 | 營運者確認 M1 證明 |
| Funded | Failed | 融資方違約或批次遭取消 |
| Milestone 1 | Milestone 2 | 營運者確認 M2 證明 |
| Milestone 1 | Failed | 融資方於 M1 階段違約 |
| Milestone 2 | Milestone 3 | 營運者確認 M3 證明 |
| Milestone 2 | Failed | 融資方於 M2 階段違約 |

### 無效轉換

下列轉換由合約明確禁止:

- **Empty → Failed** — 尚無資金的批次不會失敗,僅維持未初始化狀態。
- **Milestone 3 → Failed** — 所有里程碑完成後,託管的職能即已履行完畢:每一期款項都已撥付,金庫為空。此時已無任何資金可供退還,Failed 在此不具實質意義。這是刻意的範圍界定,而非疏漏——參見下方[結算階段的違約](#結算階段的違約)。
- **Failed → 任何狀態** — Failed 為終端狀態,不可回復或重啟。
- **任何反向轉換** — 狀態嚴格依序前進,批次不得由 Milestone 2 退回 Milestone 1。

## 結算階段的違約

EscrowVault 的職責止於 Milestone 3。融資方的還款義務是在此之後才透過存入 ClaimVault 履行,而該事件不在本狀態機的建模範圍內,本狀態機也無從強制執行。

若融資方完成全部里程碑,卻未存入約定回款,鏈上的狀態會是:批次顯示 Milestone 3、EscrowVault 為空、ClaimVault 沒有任何資金可供持有人領取。**在此情境下,沒有任何智慧合約機制可以取回參與者資金。**此階段的追償完全在鏈下進行,依靠批次部署前即已建立的三道措施:

1. **融資方質押** — 批次發行要求融資方質押一定額度的平台代幣,違約時該質押面臨風險(參見[融資方擔保機制](../Economics/Originator-Security.md))
2. **SPV 架構** — 每筆融資操作皆由一家特殊目的公司(SPV)實體承接,形成獨立於智慧合約之外的法律請求權
3. **經篩選的交易對手** — 現階段的批次是與 Planet Labs 直接合作的農場共同發行,而非透過公開的融資方上架流程

參與者應理解其中的區別:里程碑階段的保障由程式碼強制執行,結算階段的保障則由契約法與擔保品支撐。後者取決於法律程序與交易對手的清償能力,在速度與確定性上皆不及前者。請參閱[風險揭露](../Risks.md)。

## 資金撥付機制

每次里程碑轉換都會觸發一筆按比例的資金撥付予融資方。撥款排程於批次建立時定義,並寫入合約。

**三里程碑排程範例:**

| 里程碑 | 分期比例 | 累計撥付 |
|---|---|---|
| Milestone 1 | 30% | 30% |
| Milestone 2 | 35% | 65% |
| Milestone 3 | 35% | 100% |

每次撥付時:
1. 該期全額轉入融資方指定錢包——此階段不扣除任何費用,因為 3% 鑄造費已於上游的初級銷售階段收取(參見[商業模式](../Economics/Business-Model.md))
2. 狀態轉換連同時間戳記錄於鏈上

## 失敗處理

失敗的處理方式,依初級銷售是否已經結束而有所不同。

批次可自 Funding、Funded、Milestone 1 或 Milestone 2 狀態被標記為失敗。呼叫 `markFailed()` 時:

1. 代幣鑄造被鎖定,並對代幣供應量進行快照
2. **剩餘餘額**(淨額扣除已撥付的里程碑款項)被固定為退款池
3. 開啟為期 **180 天的退款窗口**,期間任何代幣持有人皆可呼叫 `claimRefund()`
4. 先前里程碑**已撥付的資金**無法透過智慧合約回收,須依賴鏈下追償程序與融資方質押罰沒機制

退款有兩項特性對參與者相當重要:

**鑄造費不予退還。**退款池是實際進入金庫的淨額,因此參與者最多只能取回其投入金額扣除已付予國庫的費用後的部分。

**退款為全有或全無。**`claimRefund()` 會在單一交易中銷毀呼叫者的全部代幣餘額,不支援部分退款。

參與者在失敗情境下的可回收金額計算方式為:

```
可回收金額 = (參與者持有代幣數 / 失敗時快照供應量) × 失敗時剩餘餘額
```

### 退款窗口結束之後

180 天窗口關閉後,營運方可呼叫 `sweepResidual()`,將任何未退還的餘額轉入由工廠設定的接收地址。**未在窗口期內申領的參與者,其退款將歸入該地址。**

請注意,暫停代幣或金庫並不會延長期限——窗口自標記失敗的時刻起固定為 180 天。

## 存取權限控管

| 操作 | 所需角色 |
|---|---|
| 初始化金庫 | BatchFactory(僅限部署時) |
| 轉換:Funding → Funded | 自動(由 PrimarySale 觸發) |
| 轉換:Funded → Milestone N | `OPERATOR_ROLE` |
| 轉換:任何狀態 → Failed | `OPERATOR_ROLE` |
| 提領(失敗情境) | 任何代幣持有人,限 180 天內 |
| 窗口結束後清掃殘餘 | `ESCROW_ADMIN_ROLE` |
| 緊急暫停 | `PAUSER_ROLE` |

## 安全特性

- **託管資金無裁量性提取** — 託管資金僅能透過里程碑撥付、退款,或窗口結束後的殘餘清掃而移動。本合約不存在開放式的提款函式。
- **重入防護** — 所有資金轉移函式皆由 OpenZeppelin 的 `ReentrancyGuard` 保護。
- **單向狀態流** — 狀態機強制執行嚴格的前向轉換,防止重放或狀態回退攻擊。
- **排程於 finalize 時固定** — 里程碑比例在呼叫 `finalize()` 時設定,之後不可變更,且總和必須為 100%。最後一期釋出剩餘餘額而非固定比例,因此捨去誤差不會使資金滯留。
- **融資方地址可變更** — 託管管理角色可在最後一期撥付前,隨時透過 `setFarmer()` 變更融資方收款地址。
