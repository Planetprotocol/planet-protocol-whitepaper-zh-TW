# 運作方式

Planet Protocol 透過**以批次為基礎的融資生命週期**運作,連結 DeFi 資金提供者與東南亞的農業生產者。每個批次代表一筆獨立且自成一體的融資操作,具有明確的時程、資產類型與回款條件。

---

## 批次生命週期

### 第一階段 — 案源建立

農業融資方(通常是合作社、集貨商或農場營運者)向 Planet Labs 提交融資申請。申請內容需載明:

- 作物種類、地理位置與生產時程
- 所需融資金額(以 USDC 計價)
- 預期回款與還款排程
- 里程碑結構(通常對應種植、生長與收成週期)

Planet Labs 透過[五層查核架構](Verification.md)執行盡職調查,評估融資方的過往紀錄、營運能力,以及底層農業操作的可行性。

### 第二階段 — 批次部署

通過審核後,Planet Labs 透過 **BatchFactory** 合約在鏈上部署新批次。這筆交易會原子性地一次建立:

- 一個新的 **PlanetRWA1155** 代幣合約,代表該批次的碎片化持份
- 一個連結的 **PrimarySale** 合約,負責代幣發行
- 一個專屬的 **EscrowVault**,依里程碑排程持有並撥付資金
- 一個連結的 **ClaimVault**,於批次完成後負責回款分配

每個批次都是完全獨立的鏈上實體。批次之間不存在交叉擔保或共用狀態。

### 第三階段 — 初級銷售

批次進入募資窗口期,DeFi 參與者可透過 PrimarySale 合約購買 ERC-1155 RWA 代幣。主要機制如下:

- **計價幣別:** 所有交易均以 USDC 進行
- **碎片化參與:** 每一枚代幣代表該批次相同比例的持份
- **固定價格:** 代幣價格於批次建立時設定,銷售期間不變動
- **鑄造費:** 每筆購買在同一筆交易中拆分——費用進入 Planet Labs 國庫,餘額直接進入 EscrowVault。費率逐批次設定,合約上限 3%。關於由此產生的批次缺口,請參閱[單位經濟](../Economics/Unit-Economics.md#鑄造費與批次缺口);完整費用結構請參閱[商業模式](../Economics/Business-Model.md)
- **份額上限,不設下限:** 批次設有最大份額數與截止時間,**不設最低募集額**——無論實際售出多少,批次皆可完成 finalize 並繼續進行

認購不足的批次不會自動退款。解除此類批次需由營運方將託管標記為失敗,屆時將針對託管中的淨額開啟 180 天退款窗口。參見[單位經濟](../Economics/Unit-Economics.md#不存在最低募集額)。

### 第四階段 — 里程碑執行

完成募資後,EscrowVault 依序通過一系列里程碑狀態:

```
Funded → Milestone 1 → Milestone 2 → Milestone 3
```

在每個里程碑:

1. 融資方提交里程碑完成的證明(例如種植確認、生長期查驗、收成文件)
2. Planet Labs 透過其查核流程驗證這些證明
3. 確認後,智慧合約撥付對應批次的資金予融資方

這種分階段撥款機制確保資金僅在現實世界進度獲得證明時才會發放。完整狀態機規格請參閱 [EscrowVault](EscrowVault.md)。

### 第五階段 — 收益分配(銷毀領取)

所有里程碑順利完成後:

1. 融資方將約定的回款金額(本金加收益)存入 **ClaimVault**
2. EscrowVault 抵達其終端狀態(Milestone 3 完成)
3. 營運方開啟領取窗口,此時對代幣供應量進行快照並固定每股給付額,窗口為期 **180 天**
4. RWA 代幣持有人透過 ClaimVault 銷毀代幣,領取相應比例的回款。窗口關閉後,未領取的資金將被掃入平台設定的地址

銷毀領取機制確保了乾淨且具確定性的結算:一枚代幣對應一次領取,銷毀即消滅該筆請求權。細節請參閱[銷毀領取機制](Burn-to-Claim.md)。

## 失敗處理

若批次在完成募資之後、最終里程碑之前失敗——無論是作物歉收、融資方違約或不可抗力——EscrowVault 將轉入 **Failed** 狀態。在此情況下:

- EscrowVault 中尚未撥付的資金開放參與者提領
- 先前里程碑已撥付予融資方的資金,則須透過鏈下追償程序處理
- 融資方質押的 $PNT 擔保品(參見[融資方擔保機制](../Economics/Originator-Security.md))可能被罰沒,作為部分損失的緩衝

**最終里程碑之後**的違約則屬於另一種情況。到那個時點,託管已撥付完所有款項且不再持有任何資金,因此不存在鏈上退款路徑;追償改為依靠 SPV 法律架構與融資方質押。詳見[結算階段的違約](EscrowVault.md#結算階段的違約)。

Planet Protocol 不保證本金返還。每個批次各自承擔獨立風險,參與者應就個別批次自行評估。

## 參與角色

| 角色 | 說明 |
|---|---|
| **DeFi 參與者** | 購買 RWA 代幣以資助批次;批次順利完成時取得收益 |
| **融資方** | 尋求融資的農業生產者或集貨商;須通過查核並質押 $PNT |
| **Planet Labs** | 平台營運方;部署批次、管理查核、營運前端介面 |
| **智慧合約** | 自主執行鏈上的資金流、狀態轉換與領取作業 |

---

## 關鍵特性

- **批次資金非代管:** 參與者資金存放於智慧合約中,不由 Planet Labs 保管。鑄造費則屬另一回事——它在購買當下即轉入 Planet Labs 國庫。
- **確定性:** 資金撥付依循預先定義的規則,合約狀態不得人工覆寫。
- **隔離性:** 每個批次在經濟上彼此獨立,單一批次失敗不會擴散至其他批次。
- **透明性:** 所有狀態轉換、資金移動與領取紀錄皆可在以太坊上查閱。
