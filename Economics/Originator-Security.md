# 融資方擔保機制

Planet Protocol 導入以 $PNT 治理代幣為基礎的**融資方質押要求**,使融資方的利益與平台表現一致,並為 DeFi 參與者提供首損緩衝。

---

## 激勵問題

在農業融資中,融資方先取得資金、後履行還款。這造成了時間上的不對稱:參與者自投資當下即承擔資金風險,而融資方的義務則是遞延的。若無相應的制衡機制,這種不對稱有利於那些表現不佳、拖延還款或違約的融資方。

傳統金融透過擔保品要求、信用評分與法律強制執行來處理這個問題。Planet Protocol 則在其[查核架構](../Protocol/Verification.md)之外,補上一道鏈上的經濟機制:**$PNT 質押**。

---

## 運作方式

### 質押門檻

融資方的批次得以在 Planet Protocol 上部署之前,必須質押一定數量的 $PNT 代幣。該質押金額在整個批次生命週期內鎖定,並具備下列作用:

1. **利益綁定** — 融資方對批次的成敗具有直接的經濟曝險
2. **首損緩衝** — 發生違約時,質押的 $PNT 可被清算以部分補償參與者
3. **品質訊號** — 願意質押代幣本身即展現融資方對自身營運的信心

### 質押參數

| 參數 | 說明 |
|---|---|
| 質押代幣 | $PNT(Planet 治理代幣) |
| 質押金額 | 依批次個別設定,與融資金額成比例 |
| 鎖定期間 | 批次生命週期全程(自部署至 Milestone 3 完成或失敗處理結束) |
| 解鎖條件 | 回款全額存入 ClaimVault |
| 罰沒條件 | 批次進入 Failed 狀態且託管中仍有未撥付資金 |

### 生命週期

```
   融資方質押 $PNT
           │
           ▼
   批次部署 ──── 批次成功 ──── $PNT 返還融資方
           │
           └──── 批次失敗 ──── $PNT 遭罰沒(部分或全部)
                                      │
                                      ▼
                              清算所得分配予
                              受影響的參與者
```

---

## 罰沒機制

若批次轉入 **Failed** 狀態:

1. 融資方質押的 $PNT 被標記為待罰沒
2. 遭罰沒的 $PNT 透過既定程序清算(出售為 USDC)
3. 清算所得按比例分配予受影響的代幣持有人
4. 罰沒依智慧合約邏輯自動執行,無需人工介入

### 罰沒的侷限

質押的 $PNT 提供的是**部分**損失緩衝,而非完全保險。可回收金額取決於:

- 質押金額相對於批次規模的比率
- 清算當時 $PNT 的市場價格
- 失敗前已撥付予融資方的託管資金比例

Planet Protocol 不保證罰沒所得足以覆蓋參與者損失。請參閱[風險揭露](../Risks.md)。

---

## 質押作為信譽機制

除經濟功能外,融資方質押也建立了一套**信譽訊號**:

- 具備成功批次紀錄的融資方會累積解鎖的 $PNT,藉此展現其可靠度
- 重複合作的融資方隨著鏈上紀錄累積,可能取得更優惠的條件(較低質押比率、較大批次規模)
- 首次合作的融資方須達到較高的質押門檻,以彌補缺乏歷史表現資料的不足

這形成了一條自然的演進路徑:從早期高摩擦、高擔保的批次,逐步走向更有效率、以關係為基礎的融資模式。

---

## $PNT 代幣狀態

$PNT 治理代幣**尚未發行**。它規劃為一項獨立的未來代幣發行,與 RWA 批次代幣有別。重點如下:

- $PNT 將作為 Planet Protocol 生態系的治理與功能型代幣
- $PNT 被用作 [Planet 積分計畫](Points-Program.md)的**空投權重**——參與者所賺取的積分將於未來的代幣生成事件轉換為 $PNT 配額
- 融資方質押機制將於 $PNT 上線後啟用

在 $PNT 發行之前,融資方擔保透過鏈下協議、查核流程與 Planet Labs 的營運監督來管理。

---

## 設計理由

| 替代方案 | 未採用的原因 |
|---|---|
| USDC 擔保品 | 佔用融資方營運資金,與提供融資的目的相牴觸 |
| 僅以 NFT 建立信譽 | 表現不佳時不產生任何經濟後果 |
| 第三方保險 | 成本高、流程慢,且東南亞多數農業營運無法取得 |
| **$PNT 質押** | **綁定利益、產生經濟後果、累積信譽,並與協議治理連結** |
